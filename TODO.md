## 🛠 Базовые правила разработки (Workflow)
*Эти правила применяются ко всем этапам и задачам ниже.*
- [ ] **Атомарные коммиты:** Выполнять `git commit` строго после каждой рабочей единицы (1 завершенный файл или 1 функция с тестами).
- [ ] **Откат вместо дебага:** Если ИИ-ассистент «ломает» код на следующем шаге, не пытаться чинить его долгим диалогом (это ухудшает контекст и качество кода). Использовать откат к последнему рабочему коммиту и формулировать задачу заново.
- [ ] **Test-Driven Development (TDD) для алгоритмов:** Любая торговая логика пишется только с `pytest`-тестами на заранее известных, вручную размеченных свечах. Не доверять ИИ реализацию логики без жестких критериев проверки.
- [ ] **Один файл / одна функция за раз:** При постановке задач агенту не просить "сделать весь модуль", разбивать задачи на минимальные смысловые блоки.
